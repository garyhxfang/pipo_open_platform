# 飞书知识库同步

文档站采用“构建前同步”模式：飞书知识库同时负责目录结构与正文内容，站点只负责网页样式和发布。

## 当前流程

1. 在 `docs-sync.config.json` 中配置知识库根节点 `rootWikiToken`。
2. 运行 `npm run prototype:sync-docs`。
3. 同步脚本递归读取根节点下的完整父子层级。
4. 每个有正文的云文档生成独立的 `public/docs-content/wiki/<node-token>.json`。
5. 完整目录树生成到 `public/docs-content/wiki-tree.json`。
6. 文档中的图片与画板预览下载到 `public/docs-media/product-whitepaper/`。
7. 文档中心根据目录树展示导航，根据节点加载对应正文。

## 目录规则

- 飞书知识库节点的顺序和父子关系会原样进入文档中心。
- 文档自身没有正文时，作为目录结构节点展示，不产生空白正文页。
- 空文档如果有子节点，默认保持展开。
- 空文档如果没有子节点，保留在目录中并显示“暂无正文”。
- 文档自身有正文时，显示为可点击的文档页。
- `docx` 与 `doc` 类型同步正文；其他对象类型保留目录位置，但当前不转换正文。

直接同步并构建：

```bash
npm run prototype:build:with-docs
```

## 自动更新

正式发布时，可在以下时机执行同步和构建：

- 每 5–15 分钟定时执行
- 飞书文档发布流程完成后触发
- 站点部署流水线开始前执行

当前原型已经具备从飞书更新站点内容的完整链路，但不会在浏览器中直接读取飞书。要做到“修改飞书后自动上线”，建议在部署流水线中运行：

```bash
npm run prototype:build:with-docs
```

如果需要接近实时更新，可以让飞书文档变更事件触发同一条构建流水线；如果不要求实时，定时任务更简单、稳定。

飞书凭证只保存在同步任务或发布环境中，不会下发到浏览器。

## 当前支持范围

当前转换器支持：

- 完整分级标题与正文
- 有序列表、无序列表、引用、Callout、链接、加粗与行内代码
- 飞书表格与分栏布局
- 图片下载、本地缓存与网页展示
- 飞书画板预览下载与展示
- 代码块

普通附件目前显示附件名称但不自动下载；复杂嵌套块会按最接近的网页结构转换。
